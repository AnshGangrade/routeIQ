# Phase 7 — product integration and verification

This phase extends the existing React/Vite application and FastAPI service. It does not change the optimization engine, historical baseline definitions, strategy schema, benchmark protocol, or historical research results.

## Workflow and integration

Home leads into the existing four-step setup. Draft state, the selected instance, calculated routes, driver selection, and experiment state survive navigation within the tab. Changed setup fields are explicitly marked as unapplied; replacing the selected plan requires confirmation.

Road setup supports an initially unselected map, coordinate entry, explicit geolocation, numbered draggable stops, confirmed removal, and a read-only location review. Synthetic layouts remain generated by the existing backend. Workload controls offer the canonical balanced range or fixed balanced counts, including empty routes when drivers outnumber stops. Road limits remain 5–99 stops; synthetic limits remain 5–200; drivers remain 1–20. Unsupported address geocoding, capacities, and time windows are not implied.

Generating a plan creates one instance and calculates the unchanged historical NN and NN + 2-Opt methods. Routes keeps the map and driver itinerary together. The additional constructor portfolio, VND, and VND + ILS options submit bounded application jobs to `POST /api/optimization/jobs`. A worker calls the existing `solve_hybrid`, then independently validates the complete fleet against the stored `FleetProblem` before publishing. Status and cancellation endpoints are scoped by job ID. No new search operator or search policy is implemented here.

The application API adds optional problem/matrix fingerprints, units, workload, feasibility, execution measurements, and per-driver comparison data. Existing endpoints and metric-only comparison records remain compatible. New jobs reject a stored matrix/problem mismatch. The UI refuses comparisons from another instance or fingerprint. Incomplete valid search results are visibly incomplete, with the actual termination reason and budget flag; failed or cancelled jobs do not overwrite earlier routes. Raw candidates and retained results have separate columns. Initial-to-final improvement refers to the best constructor reached within that run, not to training fitness or an unmeasured baseline.

The optional Strategy evolution tab uses the existing Phase 6 API. It exposes development progress, best-so-far history, population, configuration/behavior diversity, lineage, candidate configuration, evaluation failures/incompleteness, random and hand controls, provider requests, and JSON export. Source labels distinguish seeds, random proposals, mutations, crossover, live proposals, and offline proposal fixtures. A completed eligible strategy is retrieved by its experiment and candidate ID, validated, and **executed again against the current selected instance**. Its training score is never installed as an application route. The prior code-generating workflow remains available under Legacy heuristic lab.

Polling is serial, identity checked, abortable on cleanup, and time limited. Transient errors retry with visible messages. Missing jobs (404/410, e.g. after restart) terminate polling and release controls. Progress displays actual execution stages and research checkpoints; there is no invented percentage or projected distance.

Road maps draw only returned road geometry. Missing geometry leaves the relevant path absent and shows a warning, while distances retain their road-matrix units. Tile failures are distinguished from geometry failures. Synthetic map units and road meters/kilometers remain separate.

## Running the application

From the repository root, in one terminal:

```powershell
python -B -m uvicorn api.main:app --host 127.0.0.1 --port 8000
```

In a second terminal:

```powershell
Set-Location D:\routeIQ\web
npm.cmd run dev
```

Open `http://localhost:5173`. Health: `http://127.0.0.1:8000/api/health`. Vite proxies `/api` to the IPv4 loopback backend. The dev/build/preview entry point explicitly disables environment-file discovery while keeping the existing Vite configuration. Backend startup does not require an environment file. `npm.cmd run build` produces `web/dist`; a deployment must provide the matching `/api` reverse proxy.

Synthetic planning and random/hand/offline-fixture research work without external providers. Real-road routing needs reachable OSRM and map tiles. Live proposals require a locally running Ollama with the explicitly selected model; the UI's explicit starting model is `qwen3:1.7b`. No live OSRM or Ollama request was made or verified during Phase 7.

## Limits and deliberate deferrals

- This remains a local capstone service, not an authenticated multi-user deployment. Instance/results/application-job state is process-local and lost on restart; use one backend worker. Application jobs are capped at 50 retained and two active, with at most 500,000 work units and 30 solver seconds per request. The existing API/storage limits remain in effect.
- Job cancellation is cooperative. An in-flight OSRM request must reach its existing timeout before stopping; no instantaneous cancellation claim is made. Hybrid progress is stage-level; fine-grained move callbacks would require a solver interface change and were not added.
- Browser drafts/results/history survive navigation in the current tab, not a reload. Phase 6 checkpoints remain on disk and retain existing API/CLI resume support; this UI does not add checkpoint import/resume or a database.
- Workload UI offers two supported balanced policies, not arbitrary scheduling constraints. Address search is explicitly unavailable. Synthetic stops remain generated, not manually editable.
- Historical methods retain uninstrumented work counts. Different budgets are visible; no universal improvement, fair-budget benchmark, or global optimality claim follows from this application view. A zero budget can return the existing feasible ordered fallback before constructor comparisons complete.
- The optional Phase 6 view is development-only. Final validation/freezing/held-out operations remain in the existing controlled research commands. Legacy held-out metrics remain separately labelled. The 88 missing historical LLM-arm held-out measurements remain missing; the UI makes no LLM-superiority claim.
- Native map tiles, real geolocation permissions/hardware, live OSRM and live Ollama were not tested against external services. Browser tests use blocked tiles, emulated geolocation, and clearly identified road fixtures. Keyboard/screen-reader auditing beyond the semantic controls and automated interactions is still advisable.
